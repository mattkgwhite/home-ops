# Documentation Index

- [Architecture](architecture/README.md) explains the system as a whole.
- [Platforms](platforms/README.md) documents each technology domain.
- [Operations](operations/README.md) contains operational procedures.
- [Reference](reference/README.md) holds stable facts and designs.
- [Decisions](decisions/README.md) points to the ADR record.
- [Archive](archive/) preserves notes that are not current guidance.

The concise source of truth is [CURRENT-DESIGN.md](../CURRENT-DESIGN.md).
Unverified statements use a `TODO:` marker. Archived documents may describe
retired designs and must not be followed without validation.

## Obsidian and GitHub conventions

- Use relative Markdown links and one top-level heading per file.
- Prefer descriptive, lowercase kebab-case filenames.
- Do not rely on Obsidian-only features for essential information.
- Store diagram sources in `diagrams/` and shared images in `images/`.
- Link operational guidance back to the configuration it affects.
