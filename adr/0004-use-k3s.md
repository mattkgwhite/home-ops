# ADR 0004: Use K3s

- **Status:** Accepted
- **Date:** 2026-07-29
- **Owners:** TODO
- **Supersedes:** None

## Context

The current VPS documentation installs a single-node Kubernetes environment
with K3s. The environment needs a lightweight distribution that supports
standard Kubernetes resources and GitOps.

## Decision

Use K3s for the current Kubernetes cluster, disabling bundled components where
the repository supplies alternatives such as Cilium and Envoy Gateway.

## Alternatives

- kubeadm: upstream flexibility with more bootstrap and lifecycle work.
- Talos: immutable operations, but the repository content remains experimental.
- Managed Kubernetes: less control-plane work with cost and provider coupling.

## Consequences

- Low operational footprint suits a small or single-node environment.
- K3s packaging and upgrade behavior must be included in compatibility testing.
- A single node remains a workload and control-plane failure domain.
